# 视频剪辑 GIF 规范

本文规定从 MP4 等视频中剪辑 CapyLulu 动画 GIF 的选段、裁切、编码、命名和验收标准。当前主要适用于消消乐方块素材 `block/` 与奖励结算素材 `celebrate/`。

## 1. 核心原则

1. **一个 GIF 只表达一个完整、连续的动作。** 必须先理解视频内容再划分动作，不能只按固定秒数机械切片。
2. **动作连贯性优先于数量。** 同一段中如果前后出现明显不同的姿势、方向、景别或动作阶段，应拆开或只保留其中更适合的一段，不能把两个动作硬拼进一个 GIF。
3. **方块素材必须便于快速辨认。** 在 7×7 棋盘和约 56 DIP 的显示尺寸下，角色位置、轮廓和主要动作仍应稳定可辨。
4. **任何帧都不得包含平台水印、账号、字幕、搜索框或其他无关界面。** 不能只检查首帧；移动水印可能在播放过程中换位置。
5. **不为凑数降低标准。** 若视频中不足 4 段合格动作，应说明原因并让用户决定换视频或降低数量，不能交付跳切、带水印或难以辨认的片段。

## 2. 选段流程

### 2.1 先理解整段视频

剪辑前必须完整查看视频，并制作或浏览时间线接触表。至少识别：

- 镜头切换点；
- 角色动作的开始、展开、结束和回位；
- 角色位置、朝向、大小或摄像机景别的明显变化；
- 道具出现与消失；
- 字幕、水印和界面元素在各时间段的位置；
- 黑帧、转场、卡顿、重复帧和画面遮挡。

只有完成上述理解后才能确定切点。

### 2.2 动作边界

合格片段应满足：

- 开头位于动作准备完成或自然起势的位置；
- 中间没有镜头切换、突兀跳帧或语义无关动作；
- 结尾位于动作完成、短暂停顿或接近起始姿势的位置；
- 首尾循环时没有大幅位置跳跃；
- 主体没有突然由近景变远景、由正面变背面或从画面一侧瞬移到另一侧。

例如，一段视频前半是正面挥手、后半转身离开，即使总时长很短，也必须视为两个动作。用于消消乐时只选其中一个更稳定的动作，不能合成一个 GIF。

### 2.3 同一视频的素材数量

- 批量制作消消乐方块时，当前约定为**每段视频选择 4 个 GIF**。
- 4 个 GIF 应尽量覆盖不同但稳定的动作，例如轻微挥手、看向一侧、拿道具、原地小幅动作。
- “同一动作换一个相邻切点”不能算两个不同素材。
- 若用户明确指定时间范围或数量，以用户本次要求为准。

## 3. 消消乐方块 GIF（block）

### 3.1 内容要求

方块 GIF 应优先选择：

- 主体位于画面中心附近；
- 角色整体位置和占画面比例稳定；
- 动作幅度小或中等，不频繁遮挡脸部和主要轮廓；
- 背景变化小，不出现闪烁、快速推拉和大范围横移；
- 首尾姿势相近，循环播放自然；
- 与同批其他 GIF 在缩略尺寸下仍有明显区别。

应淘汰：

- 一个片段内包含两个以上明显动作；
- 转身、走出画面、突然靠近镜头等大幅位移；
- 镜头切换、转场、快速摇镜或明显画面缩放；
- 主体长期过小、被裁断或被道具完全遮挡；
- 依赖细小表情才能与其他方块区分；
- 任意一帧出现水印、字幕或应用界面。

### 3.2 技术参数

| 项目 | 标准 |
| --- | --- |
| 文件格式 | GIF89a，循环播放 |
| 画面尺寸 | `480 × 480` |
| 帧率 | `20 fps` |
| 推荐时长 | `0.8–1.5 秒` |
| 可接受时长 | `0.6–1.8 秒` |
| 色彩 | 使用独立调色板生成流程，避免明显色带和噪点 |
| 推荐体积 | 单个不超过 `4 MB` |
| 音频 | 不保留 |

当前程序会以 `BlockPlaybackRate = 0.5` 播放方块 GIF，因此导出时保留自然动作速度，不要为了“看起来慢”再次把帧延迟加倍。同类方块在棋盘中会同步播放，但每个素材自身仍必须首尾连贯。

### 3.3 构图与裁切

- 最终必须是正方形，不得拉伸人物比例。
- 优先从源视频中选取一个全程无水印的正方形安全区域，再缩放到 `480 × 480`。
- 角色头顶、手脚和关键道具必须留有安全边距；不能为了避水印把主体切残。
- `UniformToFill` 会在程序中继续裁去极少边缘，所以关键内容不要紧贴输出边界。
- 同一来源的 4 个 GIF 尽量保持主体大小接近，避免棋盘中有的只有脸、有的角色非常小。

## 4. 奖励结算 GIF（celebrate）

结算素材承载完整演出，可以比方块素材动作更大，但仍不得包含镜头跳切或水印。

- 用户给出时间范围时，严格按照指定范围剪辑。例如 `0–3`、`5–6`、`7–8` 分别输出三个 GIF，不能自行把相邻内容并入。
- 推荐时长为 `1–3 秒`；以动作语义完整为先。
- 输出尺寸和帧率仍为 `480 × 480 / 20 fps`。
- 按原始帧延迟或自然速度播放；结算 GIF 不应用方块的 0.5 倍速规则。
- 推荐单个文件不超过 `6 MB`。
- 如果片段本身不是自然循环，至少保证结尾没有黑帧、平台尾页或下一个镜头的残帧。

## 5. 水印处理

水印检查是强制项：

1. 检查整个候选时间段，而不是只检查第一帧。
2. 同时检查左上、右上、左下、右下和画面中下部；短视频平台水印可能移动。
3. 通过重新选择裁切区域排除水印，禁止使用模糊、马赛克或色块覆盖水印。
4. 裁切后若主体残缺或构图失衡，应放弃该片段。
5. 若水印覆盖主体且无法安全裁除，应向用户说明，该片段不得交付。

## 6. 输出目录与命名

### 6.1 目录

```text
gif_resources/
└─ match-game/
   ├─ block/       # 消消乐方块 GIF
   └─ celebrate/   # 奖励结算 GIF
```

临时帧、调色板、接触表和试剪文件放入 `.pet-work/` 或 `output/`，不能混入正式资源目录。

### 6.2 命名

方块素材：

```text
{来源短ID}-{两位序号}-{动作英文描述}.gif
```

示例：

```text
97da-01-front-greeting.gif
b31b-03-arms-up-cheer.gif
```

结算素材同样使用来源短 ID、序号和动作描述：

```text
61534aaa-01-smile.gif
```

要求：

- 同一来源序号从 `01` 连续排列；
- 文件名只用 ASCII 小写字母、数字和连字符；
- 动作描述必须表达实际内容，不能使用 `clip1`、`final2` 等无语义名称；
- 替换素材时尽量保持文件名稳定，避免无意义的代码和文档变更。

## 7. 推荐 FFmpeg 流程

以下命令仅作模板，`W:H:X:Y` 必须根据每段视频的安全构图和水印位置单独确定：

```powershell
ffmpeg -ss START -t DURATION -i input.mp4 `
  -filter_complex "[0:v]crop=W:H:X:Y,fps=20,scale=480:480:force_original_aspect_ratio=increase:flags=lanczos,crop=480:480,split[a][b];[a]palettegen=stats_mode=diff[p];[b][p]paletteuse=dither=sierra2_4a" `
  -loop 0 output.gif
```

注意：

- `START` 是开始时间，`DURATION` 是片段持续时间，不要把结束时间误填为持续时间。
- 必须先看画面再填写裁切参数，不能对所有视频套用同一组 `crop`。
- 调色板必须由当前片段生成，不能让所有 GIF 共用一张固定调色板。
- 导出后仍需按第 8 节逐项验收，命令成功不代表素材合格。

## 8. 验收清单

### 8.1 内容验收

- [ ] 一个 GIF 只有一个语义连贯的动作。
- [ ] 开头和结尾没有残帧、黑帧或下一动作的内容。
- [ ] 循环时人物位置、朝向和景别没有明显跳变。
- [ ] 主体完整、居中，关键部位没有被裁断。
- [ ] 所有帧均无水印、字幕、账号和无关界面。
- [ ] 同批方块在实际棋盘缩略尺寸下容易区分。
- [ ] 每段视频的 4 个方块 GIF 不是同一动作的重复切片。

### 8.2 技术验收

- [ ] 分辨率为 `480 × 480`。
- [ ] 帧率为 `20 fps`，没有异常长帧或突然加速。
- [ ] 方块时长通常在 `0.6–1.8 秒`；超出时有明确动作理由。
- [ ] GIF 能循环播放且文件可被程序解码。
- [ ] 文件体积符合用途要求。
- [ ] 文件名、序号和目录正确。
- [ ] 接触表和逐帧检查均未发现遗漏水印。

## 9. 必须交由用户决定的情况

遇到以下情况不得自行降低标准：

- 视频中不足 4 个连贯、无水印且适合方块的动作；
- 水印无法在不伤害主体构图的前提下裁掉；
- 两个动作都合格但用户只需要一个，且选择会明显影响素材风格；
- 指定时间范围内包含镜头切换或动作被截断；
- 为保持人物完整必须偏离 `480 × 480` 正方形构图；
- 同批素材在缩略尺寸下过于相似，可能影响消消乐辨认。

此时应提供候选时间段和具体问题，让用户选择换片段、换视频或调整数量。
