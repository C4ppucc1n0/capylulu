# CapyLulu 消消乐功能需求说明

## 1. 文档目的

本文只定义消消乐后续需要实现的功能、交互规则、动画流程和验收标准，不包含可运行的消消乐代码。

参考视频为用户提供的 13 秒竖屏视频。原视频不复制进仓库，仅保留经过抽帧的关键画面，方便后续开发和视觉比对。

## 2. 产品范围

首版需要实现标准交换式三消，而不是“点击方块进入收集槽”的三消玩法。

核心循环如下：

1. 用户按住一个方块并向上下左右拖动。
2. 方块与拖动方向上的相邻方块交换位置。
3. 交换后形成横向或纵向连续三个及以上同类方块时，匹配方块消除。
4. 上方方块向下落入空位。
5. 顶部生成新方块补满棋盘。
6. 新布局如果再次形成三连，继续自动消除、下落和补充，直到棋盘稳定。
7. 达到奖励触发条件后播放 Bonus Time、彩纸和用户提供的 GIF。

明确不需要：

- 点击第一个方块、再点击第二个方块来交换。
- 七格收集槽。
- 三个图块入槽后消除。

## 3. 棋盘要求

### 3.1 基础配置

- 首版建议使用 `7 × 7` 棋盘，行列数必须由常量或配置控制，不能散落为魔法数字。
- 建议准备 5–6 种辨识度高的方块。
- 正式方块素材位于 `assets/animations/match-game/block/`。每局从 24 个 GIF 中不重复随机抽取 6 个，并在本局内固定映射为六种方块；重新开始时重新抽取。方块以 0.5 倍速播放，同一种方块保持同步相位，减少盘面视觉干扰。
- 方块之间需要留有稳定间距，交换、消除和下落时不能改变棋盘整体尺寸。

### 3.2 初始棋盘生成

每次开局必须同时满足：

- 棋盘已经填满。
- 不存在开局即自动形成的横向或纵向三连。
- 至少存在一步可以形成三连的合法交换。
- 如果随机生成结果不满足以上条件，应重新生成，不能把无解棋盘交给用户。

### 3.3 无解处理

每轮连锁结算完成后检查是否仍有合法交换：

- 存在合法交换：继续等待用户拖动。
- 不存在合法交换：播放轻量洗牌提示并重新排列。
- 洗牌后的棋盘仍须满足“无天然三连、至少有一步合法交换”。

## 4. 拖动交换

拖动是唯一的方块交换方式。

### 4.1 手势识别

- 鼠标左键按下时记录起始方块和起始坐标。
- 按住左键移动超过约 `16 DIP` 后判定为拖动。
- 水平位移绝对值较大时判定为左右拖动；垂直位移绝对值较大时判定为上下拖动。
- 每次按下手势最多触发一次交换。
- 拖向棋盘外时不交换。
- 未超过阈值就松开时不执行任何操作。
- 动画结算期间锁定输入，避免同时触发多个交换。

### 4.2 交换动画

- 被拖动方块应该跟随指针产生位移反馈，不能等到松开后瞬间跳格。
- 达到交换阈值后，两个相邻方块用约 `120–180 ms` 完成位置互换。
- 交换后形成匹配：进入消除流程。
- 交换后没有形成匹配：两个方块用约 `160–220 ms` 动画退回原位。
- 无效交换不得改变棋盘数据，也不得增加奖励进度。

## 5. 匹配与消除规则

### 5.1 匹配检测

- 横向连续三个及以上相同方块属于匹配。
- 纵向连续三个及以上相同方块属于匹配。
- 四连、五连必须整段消除，不能只删除其中三个。
- 十字形、T 形和 L 形重叠匹配需要合并去重，同一方块只消除一次。
- 首版不要求生成炸弹、彩虹球等特殊方块；这些能力应留作后续扩展。

### 5.2 消除动画

- 匹配方块先播放约 `180–260 ms` 的缩放、闪光或淡出动画。
- 动画结束后才从棋盘模型中移除方块。
- 一次匹配数量较多或产生连锁时可以显示更强的粒子反馈。
- 消除过程中不能重建棋盘布局导致其他方块瞬移。

### 5.3 下落与补充

- 每一列独立结算重力。
- 空位上方已有方块按原顺序向下移动，不能随机换序。
- 顶部按缺失数量生成新方块。
- 新方块从棋盘上方进入，不应直接出现在最终位置。
- 下落动画建议为 `220–320 ms`，距离越远可以略微延长。
- 全部方块落稳后重新检测匹配，直到没有新的三连。

## 6. 奖励触发与完成演出

### 6.1 验收触发条件

目标值是 `MatchGameOptions.RewardWaveTarget` 一个常量，当前为 10 轮有效消除：

- 界面明确显示 `奖励进度 0/10` 直到 `10/10`。
- 一次“消除波次”指一次匹配检测后实际删除方块的结算。
- 连锁产生的新一轮自动消除也计为一个消除波次，所以一次三连锁算 3 轮。
- 无效交换和仅下落不增加进度。
- 达标那一轮产生后，应先完成本轮下落和可能存在的连锁结算，再进入奖励演出，避免棋盘停在半空。

改成关卡目标、分数目标或指定步数时，只应动这一个常量或它的读取处。

### 6.2 演出顺序

奖励演出严格按以下顺序播放：

1. 锁定棋盘输入。只给 **7×7 棋盘区** 加半透明深色遮罩；棋盘以外（标题栏、奖励进度、底部提示）整场亮度不变。
2. 水豚头与橙色飘带组成的 `Bonus Time` 前景从棋盘中央弹入并停留约 `1.0–1.5 秒`；前景和彩纸不跟随棋盘遮罩变暗，此时方块仍留在盘上。
3. 彩纸从棋盘区顶部落下；彩纸可以在 Bonus Time 阶段开始，并延续到 GIF 阶段。
4. Bonus Time 卡片退出。
5. 方块按反对角线逐条淡出；方块下面的蓝色 7×7 格位始终保留，整盘清空后才进入下一步。
6. 在清空出来的 7×7 棋盘区内从 `celebrate/` 中随机选择一段噜噜 GIF，按 GIF 自带帧延迟播放；
   画面按 `Uniform` 铺进棋盘区，受约束的那一边顶满、另一边居中留边。
7. GIF 播放完成后在棋盘区底部显示“继续”。
8. 点继续后棋盘整盘淡回、奖励进度归零并恢复棋盘输入。

### 6.3 GIF 资源约定

- 方块 GIF 放在 `assets/animations/match-game/block/`，当前固定为 24 个。
- 庆祝 GIF 放在 `assets/animations/match-game/celebrate/`，每次结算从当前三段中随机播放一段。
- 构建时将两组 GIF 全部内嵌进单文件 EXE，运行时不依赖外部文件。
- 播放器需要保留 GIF 的透明通道、画面比例和每帧时长。
- 缺少正式 GIF 时应明确显示“庆祝素材尚未提供”，不能静默播放不相关素材。
- 后续替换同名 GIF 并重新构建即可更新演出，不应修改游戏逻辑代码。

## 7. 状态与异常处理

建议使用明确的状态机，至少包括：

- `Ready`：等待拖动。
- `Dragging`：方块跟随指针。
- `Swapping`：交换动画中。
- `RollingBack`：无效交换退回中。
- `Clearing`：匹配消除中。
- `Falling`：方块下落和补充中。
- `Shuffling`：无解洗牌中。
- `BonusIntro`：Bonus Time 阶段。
- `Celebrating`：GIF 演出阶段。

只有 `Ready` 状态允许开始新的拖动。窗口关闭、重新开局或桌宠退出时，必须停止所有计时器和异步动画，不能让旧一局的回调继续修改新棋盘。

## 9. 验收清单

- [ ] 只能通过拖动交换方块，单击方块不会选择或交换。
- [ ] 拖动反馈跟手，并且一次手势只交换一次。
- [ ] 只能与上下左右相邻方块交换。
- [ ] 无三连的交换会播放退回动画。
- [ ] 横向和纵向三连正确消除。
- [ ] 四连、五连和交叉匹配不会漏删或重复计数。
- [ ] 消除后同列方块按顺序下落，顶部补满新方块。
- [ ] 连锁消除会一直结算到棋盘稳定。
- [ ] 开局无天然三连且至少存在一步合法交换。
- [ ] 无解时自动洗牌，洗牌结果仍然可玩。
- [ ] 奖励进度清楚显示累计消除轮次。
- [ ] 达到 `10/10` 后依次播放 Bonus Time、彩纸、逐格清场、用户提供的 GIF。
- [ ] Bonus 阶段仅棋盘被暗化，水豚飘带、彩纸和棋盘以外区域保持原亮度。
- [ ] 清场时蓝色 7×7 格位保持可见，不随方块一起消失。
- [ ] 窗口不置顶，标题栏有最小化按钮，最小化再还原后位置尺寸不变。
- [ ] 方块资源可随机选出 6 个不同 GIF；庆祝 GIF 缺失时给出明确提示。
- [ ] 动画期间输入锁定，重新开局不会受到旧动画回调影响。
- [ ] Debug 与 Release 构建均无错误。

## 10. 自动化测试建议

- 随机生成至少 1,000 个棋盘，验证无初始三连且每盘至少有一步合法交换。
- 对横向三连、纵向三连、四连、五连、T/L/十字交叉分别编写匹配用例。
- 对无效交换验证棋盘数据在回退后完全一致。
- 对多列同时消除验证重力后的方块顺序。
- 对连续三轮以上连锁验证结算终止且没有残留空位。
- 验证第一轮消除显示 `1/10`，达标那一轮稳定后才触发演出。
- 验证 24 个方块 GIF 与 3 个庆祝 GIF 均已嵌入，并验证素材缺失时的回退路径。
